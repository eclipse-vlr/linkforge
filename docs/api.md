# Как пользоваться API

При локальном запуске адрес API — `http://localhost:8080`. Примеры ниже используют его. Если приложение размещено на сервере, подставь свой адрес.

## Создать ссылку

```bash
curl -i http://localhost:8080/api/v1/links \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/article"}'
```

В ответ придёт `201 Created` и JSON:

```json
{
  "code": "aB23cdEf",
  "short_url": "http://localhost:8080/aB23cdEf",
  "original_url": "https://example.com/article"
}
```

Код каждый раз новый. Если на сервере задана `CREATE_LINK_API_KEY`, добавь заголовок `X-API-Key` с её значением. Пример запроса для PowerShell есть в [README](../README.md).

Принимается один JSON-объект с единственным полем `url` в нижнем регистре. Значение — HTTP/HTTPS-адрес длиной до 4096 байт. Всё тело запроса должно укладываться в 16 КиБ. Лишние и повторяющиеся поля отклоняются.

## Перейти по ссылке и посмотреть статистику

Открой `short_url` в браузере — сервер вернёт `302` и адрес исходной страницы в заголовке `Location`. Чтобы посмотреть ответ без перехода, используй `curl -i` со своей короткой ссылкой.

Статистика доступна по `GET /api/v1/links/{code}/stats`. Подставь код из ответа создания: восемь латинских букв или цифр. Некорректный код в адресе перехода или статистики возвращает `404`. Например:

```json
{"code":"aB23cdEf","click_count":3}
```

Статистика публичная. Повторные переходы и боты тоже считаются. Если записать счётчик не удалось, переход всё равно сработает, но в статистику он может не попасть.

## Проверить, что сервер отвечает

`GET /healthz` возвращает `{"status":"ok"}`. Это проверка HTTP-сервера, без проверки подключения к PostgreSQL и Redis.

## Если что-то пошло не так

Ошибки приходят обычным текстом.

| Код | Что проверить |
|---|---|
| `400` | JSON и адрес в поле `url` |
| `401` | Заголовок `X-API-Key`, если включена защита |
| `404` | Код ссылки: такой ссылки нет |
| `405` | HTTP-метод; разрешённый указан в `Allow` |
| `413` | Размер тела: больше 16 КиБ |
| `429` | Превышен лимит: 10 запросов на создание с одного IP за 60 секунд |
| `503` | Лимитер не может принять новый IP-адрес |
| `500` | Логи сервера: произошла внутренняя ошибка |

При `429` и `503` заголовок `Retry-After` подсказывает, через сколько секунд повторить запрос. Ошибочные POST-запросы тоже занимают квоту.

Полная спецификация для Swagger и других инструментов — в [openapi.yaml](openapi.yaml).
