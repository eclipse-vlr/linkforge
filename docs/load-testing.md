# Нагрузочное тестирование LinkForge

## Что проверяется

Скрипт [`cmd/loadtest`](../cmd/loadtest/main.go) делает один `POST /api/v1/links`, затем ограниченное число запросов `GET /{code}`. Клиент **не переходит** по адресу из `Location`, поэтому не создаёт нагрузку на сторонний сайт.

Тест измеряет:
- количество запросов и одновременно работающих клиентов;
- успешные HTTP 302, неожиданные HTTP-статусы и сетевые ошибки;
- время выполнения и число успешных перенаправлений в секунду;
- p50/p95/p99 задержки успешных ответов.

Метрики относятся только к выбранному сценарию, среде и настройкам. В частности, создание ссылок имеет собственный лимитер, поэтому серия POST-запросов не годится для проверки пропускной способности редиректов.

## Автоматический прогон

В [GitHub Actions](../.github/workflows/loadtest.yml) настроен отдельный тест с настоящими PostgreSQL 17 и Redis 7. На каждый запуск проверяются **500 GET-запросов, 10 клиентов**, а JSON-отчёт сохраняется как артефакт **`linkforge-loadtest-report`** на 14 дней.

Workflow выполняется при изменении собственного YAML-файла или `cmd/loadtest` в `master`, а также запускается вручную через **Actions → LinkForge Load Test → Run workflow**.

**Результаты:** пока здесь не опубликованы. Числа нужно брать из фактически завершившегося GitHub Actions (артефакт `loadtest.json`), а не из примеров. Отдельно отмечать дату, commit SHA, окружение и был ли активен Redis.

## Локальный запуск (PowerShell)

```powershell
docker compose up -d --wait db redis
$env:REDIS_URL = "redis://127.0.0.1:6379/0"
# В первом терминале:
go run ./cmd/api

# Во втором терминале:
go run ./cmd/loadtest -base http://127.0.0.1:8080 -requests 500 -workers 10 -out loadtest.json
```

Скрипт специально разрешает **только локальные HTTP-адреса** с портом и ограничивает число запросов (1–10 000) и клиентов (1–50). Он не предназначен для нагрузочного тестирования чужих или публичных серверов.

## Как фиксировать результаты

Для каждого прогона записываем:
- commit SHA и дату;
- характеристики машины/CI runner и число клиентов;
- Postgres / Redis (включён или выключен);
- долю ошибок, RPS, p50/p95/p99 из отчёта;
- выводы и ограничения измерения.

Не стоит сравнивать результаты разных запусков, не указав условия. Кроме того, редирект может вернуть 302 даже при сбое записи счётчика переходов — эта проверка измеряет HTTP-ответ, но сама по себе не доказывает точность статистики.
