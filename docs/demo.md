# Демонстрация LinkForge на собеседовании

Сценарий занимает около пяти минут после первой сборки образа. Нужны Docker с Compose и PowerShell 7.2 или новее. Go устанавливать не нужно.

Из корня репозитория:

```powershell
pwsh -File ./scripts/demo.ps1
```

Если порт 18081 занят, выбери другой:

```powershell
pwsh -File ./scripts/demo.ps1 -Port 18082
```

Сценарий создаёт отдельный Compose-проект со своей БД, Redis и тестовым API-ключом. После проверки он удаляет только свои контейнеры, сеть и том с демонстрационными данными. Клиент не переходит по адресу из `Location`: проверяются ответ `302` и заголовок, внешний сайт не получает запросов.

## Что показать и объяснить

| Шаг | Наблюдаемый результат | Что сказать |
|---|---|---|
| API-ключ и валидация | Без ключа — `401`, с некорректным URL — `400` | Защита создания ссылок необязательна; входные данные проверяются до записи в БД |
| Создание | `201`, код из восьми символов, счётчик `0` | Код генерируется через `crypto/rand`, уникальность обеспечивает PostgreSQL |
| Два перехода | Два ответа `302`, правильный `Location`, счётчик `2` | Счётчик увеличивается атомарным SQL-запросом |
| Кеш | URL есть в Redis, TTL положительный | Кешируется URL; счётчик всегда обновляется в PostgreSQL |
| Отказ Redis | Редирект сохраняется, счётчик становится `3` | Кеш ускоряет чтение, основное хранилище — PostgreSQL |
| Остановка | В логах `HTTP server stopped`, код выхода `0` | SIGTERM запускает graceful shutdown; Compose даёт ему 15 секунд |

## Короткий рассказ

«LinkForge — мой учебный сервис сокращения ссылок на Go. Он создаёт короткую ссылку, перенаправляет на исходный адрес и хранит статистику переходов.

Обработчики используют интерфейс `LinkRepository`. Основная реализация работает с PostgreSQL через `pgxpool`, а отдельная обёртка добавляет кеш Redis с TTL. Это позволяет тестировать обработчики без внешних сервисов и отдельно проверять интеграцию с настоящей БД и кешем.

Также есть ограничение создания ссылок по IP, необязательный API-ключ, структурированные логи, таймауты и корректная остановка. В CI запускаются тесты с PostgreSQL и Redis, проверка гонок и уязвимостей, сборка и проверка Docker-образа».

## К чему быть готовым

- При попадании в кеш PostgreSQL всё равно нужен для счётчика. Redis не делает редирект независимым от БД.
- Лимитер работает в памяти одного процесса. Клиенты за одним NAT или прокси делят квоту.
- Статистика публичная и приблизительная: ошибка записи счётчика не блокирует редирект.
- Нагрузочные измерения привязаны к окружению. Результат GitHub Actions не определяет производительность будущего публичного сервера.
