# LinkForge v0.1.0

> Опубликован 23 октября 2026 года: [v0.1.0](https://github.com/eclipse-vlr/linkforge/releases/tag/v0.1.0).

В первой версии можно создать короткую ссылку, перейти по ней и посмотреть число переходов. [Описание API](openapi.yaml).

## Что вошло

- Хранение ссылок и статистики в PostgreSQL 17, миграции при запуске.
- Необязательный кеш Redis с обращением к базе при его сбое.
- Ограничение создания ссылок по IP и защита через `X-API-Key`.
- Проверка входных данных, ограничения запросов, логи и корректная остановка сервера.
- Docker-образ и готовые сборки: Linux и macOS для amd64/arm64, Windows для amd64.

## Что проверить перед выпуском

Для выбранного коммита должны пройти **Go CI** и **HTTP benchmark**. CI запускает тесты с PostgreSQL и Redis, проверяет гонки и уязвимости, собирает Docker-образ и проверяет его работу. Нагрузочный тест выполняет 500 запросов в 10 потоков.

При подготовке архивов отдельно запускается распакованная Linux-сборка: проверяются API-ключ, 500 редиректов, сохранение статистики и остановка сервера.

## Ограничения

Лимитер работает в памяти одного экземпляра. Статистика публичная, включает повторные обращения и ботов. При ошибке записи счётчика редирект продолжит работать, поэтому часть переходов может не попасть в статистику.

Настройки Compose предназначены для компьютера разработчика. Для хостинга нужны свои секреты, настройки доступа и резервные копии базы.

## Подготовка и публикация

Для v0.1.0 эти шаги уже выполнены. Порядок сохранён для справки; повторный запуск workflow не изменит опубликованный выпуск.

1. Дождись зелёного **Go CI** нужного коммита в `master`.
2. Открой **Actions → Prepare draft release → Run workflow**, выбери `master` и `v0.1.0`.
3. Дождись завершения сборки. В черновике появятся архивы для пяти платформ, исходники, параметры сборки, отчёт и `SHA256SUMS`.
4. Открой черновик в **Releases**, проверь описание и файлы. Для публикации нажми **Publish release**.

В каждом архиве есть программа, миграции, OpenAPI и инструкция `README.md`. Workflow проверяет размеры и SHA-256 загруженных файлов; копия сохраняется в артефактах Actions на 14 дней.

Workflow готовит только черновик и не меняет опубликованный выпуск. Если в черновике уже есть сборки от другого коммита, он остановится, чтобы не смешать версии.

Если Git-тег версии уже существует, он должен указывать на коммит сборки. Это проверяется до загрузки и после неё, в том числе для аннотированных тегов. До публикации черновик может оставаться без тега.
