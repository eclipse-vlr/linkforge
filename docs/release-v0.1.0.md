# LinkForge v0.1.0 — заметки к выпуску

> Кандидат в первый релиз. Тег `v0.1.0` и GitHub Release ещё не опубликованы. Публикуй выпуск от проверенного коммита основной ветки `master` после успешного завершения обоих workflow.

## Возможности версии

- REST API для создания коротких ссылок, перехода по коду и просмотра количества переходов.
- Хранение ссылок и счётчиков в PostgreSQL 17, SQL-миграции при запуске.
- Опциональное кеширование в Redis с возвратом к PostgreSQL при проблемах с кешем.
- Лимит создания ссылок по IP, проверка входных данных и ограничения размера запроса.
- Опциональный заголовок `X-API-Key` для защиты создания ссылок при заданной `CREATE_LINK_API_KEY`.
- HTTP-таймауты, структурированные логи и корректное завершение сервера.
- Автоматические и интеграционные тесты, GitHub Actions.
- [OpenAPI-спецификация](openapi.yaml) для существующих маршрутов.
- Go 1.27.3 с исправлением GO-2026-6809; строгая проверка JSON и параметров подключения к Redis.
- Docker-образ с запуском от обычного пользователя и поддержкой переменной `PORT`.

## Известные ограничения

- Это MVP для демонстрации и обучения, не публичный сервис без дополнительной защиты от злоупотреблений.
- Лимитер хранится в памяти и не работает как общий лимит для нескольких экземпляров.
- Счётчик переходов может недосчитаться при ошибках базы, редирект при этом продолжит работать.
- Статистика публичная, учитывает ботов и повторные переходы.
- Compose из репозитория предназначен для локальной разработки, тестовый пароль нельзя использовать на публичном сервере.

## Проверки кандидата

Для выбранного коммита должны успешно завершиться:

- **Go CI**: тесты с PostgreSQL и Redis, `-race`, `go vet`, `govulncheck`, сборка Docker-образа, запуск миграций и проверка API внутри контейнера. Проверяются `PORT`, запуск без root, `401` без ключа, создание ссылки, редирект, статистика и корректная остановка.
- **HTTP benchmark**: 500 запросов в 10 потоков к настоящему локальному API с PostgreSQL и Redis. Результат сохраняется в артефакт `linkforge-benchmark`.

Локально также проверен Docker-образ в трёх режимах: только PostgreSQL, PostgreSQL с Redis и PostgreSQL при недоступном Redis. Во всех режимах работают авторизация, редиректы, статистика и завершение сервера. Ошибки `REDIS_URL` отклоняются до подключения к базе.

## Подготовка и публикация

После зелёного **Go CI** запусти **Actions → Prepare draft release → Run workflow** для ветки `master` и версии `v0.1.0`. Workflow проверяет CI именно выбранного коммита и готовит:

- Linux и macOS для amd64/arm64, Windows для amd64.
- Инструкцию запуска, миграции и OpenAPI внутри каждого дистрибутива.
- Архив исходников, параметры сборки, результаты проверки и SHA256SUMS.
- Свежий отчёт: 500 запросов к распакованному Linux-дистрибутиву с PostgreSQL и Redis, проверка авторизации, статистики и корректной остановки.

Файлы загружаются в **черновик** GitHub Release. Workflow сверяет размеры и SHA-256 на GitHub с локальными файлами и сохраняет копию в артефактах Actions на 14 дней. Публичный выпуск автоматически не создаётся; уже опубликованный выпуск workflow не изменяет.

Открой подготовленный черновик в **Releases**, проверь описание и файлы, затем нажми **Publish release**. [Инструкция запуска готового дистрибутива](running-binary.md).
