# Развёртывание LinkForge (подготовка, не публичный стенд)

> Пока здесь **нет рабочего публичного URL**. Dockerfile подготовлен, но образ ещё не был собран и проверен на хостинге. Эти шаги не означают, что приложение уже опубликовано.

## Требования

- Docker-хостинг, умеющий собирать корневой [`Dockerfile`](../Dockerfile), например Railway.
- PostgreSQL с постоянным хранилищем и отдельным паролем. Redis — необязателен.
- Переменные окружения должны храниться в секретах хостинга, а не в GitHub.
- **Один экземпляр приложения:** миграции выполняются при старте, а лимитер по IP хранится в памяти процесса.

## Сценарий для Railway

1. Подключи репозиторий `eclipse-vlr/linkforge` к сервису Railway, выбери сборку из `Dockerfile`.
2. Создай PostgreSQL в том же Railway-проекте. Передай сервису API `DATABASE_URL` из приватного подключения к базе через переменные Railway. Не используй тестовый пароль из `docker-compose.yml`.
3. Redis можно не подключать: если `REDIS_URL` пустой, приложение работает напрямую с PostgreSQL. Если подключать Redis, передай корректный `redis://` или `rediss://` URL из переменных.
4. Railway задаёт `PORT`; команда запуска в Dockerfile настраивает `HTTP_ADDR` на `0.0.0.0:$PORT`. При необходимости можно явно определить `HTTP_ADDR`.
5. Сгенерируй публичный домен для сервиса. Укажи `BASE_URL=https://<твой-домен>` без пути, query или завершающего слеша. После изменения `BASE_URL` перезапусти приложение.
6. Проверь логи миграций и подключения к PostgreSQL. Затем проверь `GET /healthz`, создание ссылки, ответ `302` и статистику переходов. `/healthz` сам по себе **не** проверяет БД.
7. Только после проверки реального URL добавь его в профиль GitHub.

## Почему публичная демонстрация требует осторожности

API сейчас позволяет любому пользователю создавать перенаправления на произвольные HTTP/HTTPS URL. Такой сервис можно использовать для спама или фишинга. Лимитер в памяти **не** заменяет авторизацию, квоты и защиту от злоупотреблений.

Для открытого интернета прежде чем делиться ссылкой рекомендуется как минимум добавить ограничение доступа к созданию ссылок, мониторинг и резервные копии PostgreSQL. Пока безопаснее закрытый тестовый стенд.

## Локальная проверка Docker-образа

```powershell
docker build -t linkforge:local .
docker compose up -d --wait db
docker run --rm -p 127.0.0.1:8080:8080 `
  -e DATABASE_URL='postgres://linkforge:devpassword@host.docker.internal:5432/linkforge?sslmode=disable' `
  -e BASE_URL='http://localhost:8080' linkforge:local
```

Эта команда рассчитана на Docker Desktop под Windows; `host.docker.internal` на других системах может требовать отдельной настройки. Команды не проверены в данном окружении.
