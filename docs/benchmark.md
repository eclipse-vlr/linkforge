# Нагрузочное тестирование

В проекте есть [небольшая утилита](../cmd/loadtest/main.go): она создаёт одну ссылку, затем много раз запрашивает редирект. По самой ссылке утилита не переходит, поэтому внешнему сайту нагрузка не достаётся.

## Как запустить

Подними API по [инструкции из README](../README.md) и оставь его работать. В другом терминале из корня проекта выполни:

```bash
go run ./cmd/loadtest -base http://127.0.0.1:8080 -requests 500 -workers 10 -out loadtest-local.json
```

Команда подходит и для PowerShell. Она отправит 500 запросов в 10 потоков и запишет результат в `loadtest-local.json`.

Если API запущен с `CREATE_LINK_API_KEY`, задай ту же переменную во втором терминале. Утилита передаст ключ только при создании ссылки.

Для проверки используй тестовую базу: каждый запуск добавляет новую ссылку. По умолчанию утилита работает только с API на этом же компьютере. Ограничения — 10 000 запросов и 50 одновременных клиентов.

## Что смотреть в отчёте

| Поле | Что означает |
|---|---|
| `successful_redirects` | Сколько раз получен ожидаемый ответ `302` |
| `unexpected_responses`, `network_errors` | Другие HTTP-ответы и сетевые ошибки |
| `requests_per_second` | Среднее число запросов в секунду |
| `p50_milliseconds`, `p95_milliseconds`, `p99_milliseconds` | Время, за которое уложились 50%, 95% и 99% запросов |

Начни с проверки ошибок, затем сравнивай скорость и задержки. Сохраняй вместе с отчётом коммит, параметры запуска, сведения о компьютере и то, был ли включён Redis.

На каждом переходе обновляется счётчик в PostgreSQL, даже если URL найден в кеше. Поэтому результат зависит и от базы. Этот тест проверяет переходы; он не измеряет скорость создания ссылок.

## Проверка на GitHub

[HTTP benchmark](../.github/workflows/benchmark.yml) поднимает PostgreSQL и Redis, запускает API и выполняет те же 500 запросов в 10 потоков. Он запускается при изменении API, миграций, зависимостей или самой утилиты. Его можно запустить вручную через **Actions → HTTP benchmark → Run workflow**.

Отчёт лежит в артефакте `linkforge-benchmark` и хранится 14 дней. Отчёт проверки готовой Linux-сборки также приложен к [релизам](https://github.com/eclipse-vlr/linkforge/releases). Для сравнения результатов используй коммит и параметры из отчёта.

Замеры на GitHub Actions могут отличаться от результатов на твоём компьютере. По ним нельзя судить о скорости будущего публичного сервера.
