# Нагрузочное тестирование LinkForge

В репозитории есть небольшая утилита [`cmd/loadtest`](../cmd/loadtest/main.go), которая отправляет **реальные HTTP-запросы** в локально запущенный LinkForge.

## Что проверяем

- Создаём **одну** тестовую ссылку через `POST /api/v1/links`.
- Отправляем заданное количество параллельных `GET /{code}`.
- **Не следуем** `Location`: никакие внешние сайты не получают нагрузку.
- Замеряем успешные `302`, остальные статусы, сетевые ошибки, запросы в секунду, p50/p95/p99.
- По умолчанию инструмент разрешает только loopback-адрес и ограничивает нагрузку: максимум 10 000 запросов и 50 одновременных клиентов.

Это не измеряет производительность в публичном интернете, не моделирует разные IP и не проверяет RPS создания ссылок (для него есть лимитер).

## Как запустить в Windows PowerShell

В одном окне PowerShell из корня репозитория:

```powershell
docker compose up -d --wait db redis
$env:REDIS_URL = 'redis://127.0.0.1:6379/0'
go run ./cmd/api
```

Во втором окне из того же каталога:

```powershell
go run ./cmd/loadtest -base http://127.0.0.1:8080 -requests 500 -workers 10 -out loadtest-local.json
```

Для сравнения можно повторить с `-workers 1`, `-workers 10` и `-workers 30`. Тест создаёт новые ссылки, поэтому запускай его в **тестовой базе**, а не с реальными данными.

## Как фиксировать результат

Вывод утилиты — JSON со статусами ответов, количеством успешных редиректов, RPS, длительностью и задержками p50/p95/p99. Сохрани JSON вместе с такими данными:

| Параметр | Что указать |
|---|---|
| Дата и commit | Когда и на каком коммите запускался тест |
| Среда | ОС, CPU, RAM, Go и Docker |
| PostgreSQL и Redis | Версии и запущен ли кеш |
| Параметры | `requests`, `workers`, адрес |
| Ошибки | Количество не-302 и сетевых ошибок |
| Результаты | RPS, p50, p95 и p99 из реального вывода |

**Фактические цифры пока не опубликованы:** у автора изменений не было доступного запущенного экземпляра LinkForge и среды Docker с PostgreSQL. Не используем вымышленные измерения. Когда замеры будут выполнены, результат можно добавить в `docs/benchmarks/` с указанием среды.

## На что обратить внимание

На каждом редиректе увеличивается счётчик в PostgreSQL, даже если URL найден в Redis. Поэтому результаты зависят не только от кеша, но и от работы БД. Повторные тесты на CI-hosted runners могут заметно отличаться от измерений на твоём компьютере.
